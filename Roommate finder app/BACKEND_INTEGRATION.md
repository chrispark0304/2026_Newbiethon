# 같이살집 — 백엔드 연동 명세

프론트엔드(`src/App.tsx`)는 현재 목데이터(`PROPERTIES`, `ROUTES`)로 3개 화면을 돌리고 있습니다.
이 문서는 그 목데이터를 실제 API 응답으로 교체하기 위해 백엔드가 무엇을 줘야 하는지 정리한 것입니다.

## 화면 흐름 & 필요한 시점

```
Screen 1 (조건 입력)                Screen 2 (지도 + 목록)              Screen 3 (매물 상세 + 경로)
─────────────────────              ──────────────────────             ──────────────────────────
사람1/2: 직장, 월세범위, 평수범위   매물 목록 + 지도 마커               경로(지하철/버스 구간), 통근시간
        │  "같이 살자" 클릭 →              │  매물 클릭 →
        └────────────────────────────────►└──────────────────────────►
              (A) 직장 지오코딩              (B) 매물 검색                (C) 통근 경로 조회
              (필요 시)                                                    (매물별로 lazy 호출)
```

## (A) 직장 위치 지오코딩

사용자가 "강남역", "판교역" 처럼 자유 텍스트로 입력하는 직장 위치를 좌표로 변환합니다.

```
GET /api/geocode?query=강남역
```

**응답**
```json
{ "name": "강남역", "lat": 37.4979, "lng": 127.0276 }
```

카카오/네이버 로컬 API를 그대로 프록시해도 되고, 자체 지오코더를 붙여도 됩니다. 프론트는 이 좌표를 (B)/(C) 요청에 그대로 넘깁니다.

## (B) 조건에 맞는 매물 검색

Screen 1 → Screen 2 전환 시 호출.

```
POST /api/listings/search
Content-Type: application/json

{
  "p1": { "workLat": 37.4979, "workLng": 127.0276, "priceMin": 30, "priceMax": 70, "areaMin": 15, "areaMax": 35 },
  "p2": { "workLat": 37.5563, "workLng": 126.9236, "priceMin": 40, "priceMax": 80, "areaMin": 20, "areaMax": 40 }
}
```

**응답** — `Listing[]`

```json
[
  {
    "id": 1,
    "price": 51,
    "deposit": 500,
    "neighborhood": "마포구 합정동",
    "address": "합정로 45",
    "floor": 3,
    "area": 24,
    "year": 2018,
    "lat": 37.5495,
    "lng": 126.9139
  }
]
```

| 필드 | 타입 | 단위 | 비고 |
|---|---|---|---|
| `id` | number | - | 매물 고유 ID |
| `price` | number | 만원/월 | 월세 |
| `deposit` | number | 만원 | 보증금 |
| `neighborhood` | string | - | "구 동" 표기 |
| `address` | string | - | 도로명 또는 지번 |
| `floor` | number | - | 지하는 음수 (예: -1) |
| `area` | number | 평 | |
| `year` | number | - | 건축년도 |
| `lat`, `lng` | number | 위도/경도 | **아래 "지도 좌표" 항목 참고** |

## (C) 매물별 통근 경로 (지하철/버스 구간)

Screen 2에서 매물을 클릭해 Screen 3로 들어갈 때, 그 매물 하나에 대해서만 호출합니다 (목록 전체에 대해 미리 계산할 필요 없음).

```
GET /api/listings/1/commute?p1WorkLat=37.4979&p1WorkLng=127.0276&p2WorkLat=37.5563&p2WorkLng=126.9236
```

**응답**

```json
{
  "p1": {
    "minutes": 28,
    "stops": [
      { "name": "합정",   "lat": 37.5495, "lng": 126.9139 },
      { "name": "당산",   "lat": 37.5346, "lng": 126.9026, "mode": "subway", "line": "2호선" },
      { "name": "여의도", "lat": 37.5219, "lng": 126.9245, "mode": "subway", "line": "9호선" },
      { "name": "강남",   "lat": 37.4979, "lng": 127.0276, "mode": "bus",    "line": "740" }
    ]
  },
  "p2": {
    "minutes": 12,
    "stops": [
      { "name": "합정",     "lat": 37.5495, "lng": 126.9139 },
      { "name": "홍대입구", "lat": 37.5572, "lng": 126.9245, "mode": "subway", "line": "2호선" }
    ]
  }
}
```

**규칙**
- `stops[0]`은 항상 매물 위치(출발점)이며 `mode`/`line`이 없습니다.
- 이후 각 stop의 `mode`/`line`은 "이전 stop → 이 stop" 구간이 무엇으로 이동하는지를 나타냅니다.
- `mode`는 `"subway"` 또는 `"bus"` 둘 중 하나만.
- `line`은 지하철이면 `"2호선"`, `"9호선"`, `"경의중앙선"`처럼, 버스면 노선 번호 문자열(`"740"`)로. 프론트엔드가 지하철 노선은 실제 서울 지하철 노선 색상으로, 버스는 파란 점선으로 자동으로 그려줍니다 (`LINE_COLORS` in `src/App.tsx` — 새 노선이 오면 여기 색상표에 추가해야 함, 없으면 기본 회색으로 표시됨).
- `minutes`는 도보+환승 포함 총 소요시간(분), 정수.

이 부분은 자체 로직으로 구현하기보다 **ODsay 대중교통 API** 또는 **카카오모빌리티 길찾기 API** 응답을 위 스키마로 변환해서 내려주는 걸 추천합니다. 두 API 모두 지하철/버스 구간별 노선명·정류장 좌표를 제공합니다.

## 지도 좌표에 대해 (중요, 결정 필요)

현재 프론트엔드는 실제 지도가 아니라 **가짜 배경 위에 %좌표(x, y: 0~100)**로 마커를 찍는 방식입니다 (`src/App.tsx`의 `MapBackground`, `WorkMarker` 등). 실제 서비스로 가려면 둘 중 하나를 정해야 합니다.

1. **실제 지도 SDK 도입 (추천)** — 카카오맵/네이버맵 JS SDK를 붙이고, 백엔드는 이 문서대로 **위도/경도(lat/lng)만** 내려주면 됩니다. 프론트에서 지도 SDK가 알아서 화면 좌표로 변환해줘서 별도 x/y 계산이 필요 없습니다.
2. 지금 방식(가짜 배경 + %좌표) 유지 — 이 경우 백엔드가 위경도 대신 이미 정규화된 x/y(0~100)를 내려줘야 하는데, 화면 확대/축소·다른 지역 대응이 안 되므로 데모 이후엔 권장하지 않습니다.

→ **1번(위경도 + 실제 지도 SDK)로 간다고 가정하고 위 스키마를 작성했습니다.** 다르게 갈 경우 알려주세요.

## 매물 원본 데이터 (참고용)

목데이터 대신 채울 실거래가 원본 데이터가 프로젝트 루트에 있습니다.

- `rtms_같이살집_최종_202608.csv` — 국토교통부 실거래가(연립다세대 전월세, 2026년 8월, 서울) 중 앱에 나온 동네만 추린 것. 컬럼: 동네, 시군구, 번지, 건물명, 위도, 경도, 전월세구분, 전용면적(㎡), 층, 보증금(만원), 월세금(만원), 건축년도.
- **주의**: 이 CSV의 위도/경도는 (무료 지오코더 한계로) **건물 단위가 아니라 법정동(동) 단위** 좌표입니다. 같은 동이면 여러 매물이 같은 좌표를 공유합니다. 매물 마커를 지도에 정확히 찍으려면 `시군구 + 번지`를 카카오/네이버 지오코딩 API로 다시 돌려서 건물 단위 좌표로 보정하는 걸 권장합니다.
- 전용면적(㎡)은 프론트가 쓰는 "평" 단위와 다릅니다. 변환: `평 = ㎡ / 3.3058`.

## 요약: 백엔드가 만들어야 할 것

| 엔드포인트 | 역할 | 우선순위 |
|---|---|---|
| `GET /api/geocode` | 직장 텍스트 → 좌표 | 중 (프론트에서 카카오 SDK로 자체 처리해도 됨) |
| `POST /api/listings/search` | 조건에 맞는 매물 목록 | 높음 |
| `GET /api/listings/:id/commute` | 매물 하나에 대한 두 사람 통근 경로 | 높음 |
