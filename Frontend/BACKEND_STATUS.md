# 백엔드 연동 현황

`BACKEND_INTEGRATION.md` 명세에 대한 구현 상태. 서버는 `uvicorn api.main:app --port 8000`,
문서는 http://localhost:8000/docs.

| 엔드포인트 | 상태 | 비고 |
|---|---|---|
| `GET /api/geocode` | ✅ | 카카오 로컬 프록시 (키워드 → 주소 순으로 탐색) |
| `POST /api/listings/search` | ✅ | 명세 스키마 그대로 + 부가 필드 4개 |
| `GET /api/listings/:id/commute` | ✅ | 카카오 대중교통 1순위, 실패 시 자체 엔진 폴백 |

`KAKAO_REST_API_KEY` 환경변수가 필요하다. 없으면 `/api/geocode`는 503,
`commute`는 자체 엔진(지하철 전용)으로 동작한다.

## `POST /api/listings/search` 필터링

```
① 전체 매물                    8,317
② 환산월세(합산 범위) 통과       7,330
③ 면적(합산 범위) 통과          3,430
④ 통근 경로 존재                3,394
⑤ 통근 한도 60분 이내           2,900대
⑥ 공동 적합도로 정렬
⑦ 같은 건물 1건 / 같은 동 3건 제한
⑧ limit(기본 60) 만큼 반환
```

**정렬은 통근시간이 아니라 공동 적합도(`jointScore`)다.** 가격·면적·통근을 함께 보고
두 사람 만족도 **격차에 벌점**을 준다. 통근시간만으로 정렬하면 예산 상한에 딱 붙은 비싼 집과
훨씬 싼 집이 동급이 되고, 한 사람만 가까운 집이 위로 올라온다.

### 필터 파라미터 (전부 선택, 안 보내면 기본값)

| 파라미터 | 기본 | 역할 |
|---|---|---|
| `commuteLimitMin` | 60 | 더 오래 걸리는 쪽이 이 값을 넘으면 제외. 0이면 제한 없음 |
| `maxPerBuilding` | 1 | 같은 건물 최대 노출 수. 실거래가는 호실별로 여러 건 잡힌다 |
| `maxPerDong` | 3 | 같은 법정동 최대 노출 수. 두 직장 사이 동네가 목록을 덮는 걸 막는다 |
| `limit` | 60 | 반환 개수 |

제한을 끄면 상위 60건이 11개 동에 몰리고 최다 동네가 11건을 차지한다.
기본값에서는 **40개 동 · 최다 3건 · 중복 건물 0개**가 된다.

### 목록에 통근시간이 같이 온다

`commuteMinutes: [p1분, p2분]`과 `jointScore`가 응답에 포함된다.
**Screen 2 카드에 통근시간을 띄우려고 `/commute`를 미리 호출할 필요가 없다.**
`/commute`는 상세 화면에서 경로(정류장·노선)가 필요할 때만 부르면 된다.

### 걸러낸 비정상 데이터

국토부 원본에 보증금 30만원짜리 "전세" 같은 행이 섞여 있다(입력 오류나 특수관계 거래로 보인다).
점수 산식이 "쌀수록 좋다"라 그대로 두면 목록 1위로 올라오므로, **환산월세 20만원 미만 32건**을
제외한다. 환산월세 1퍼센타일이 26만원이라 보수적인 선이다. `/api/health`의 `dropped_outliers`로 확인.

## 명세와 다르게 간 것 (확인 필요)

### 1. `priceMin/Max`, `areaMin/Max`를 **두 사람 합**으로 해석했다

명세는 사람별로 범위를 받는데 집은 하나다. 그래서 각자 부담할 몫으로 보고 더해서 비교한다.

```
p1.priceMax 70 + p2.priceMax 80  →  총 월세 150만원까지의 매물
p1.areaMax 12평 + p2.areaMax 12평 →  총 24평까지의 매물
```

"둘 다 만족해야 한다"(교집합)로 읽을 수도 있는데, 그러면 더 싼 쪽 예산이 상한이 되어
합산 예산의 의미가 사라진다. 다르게 원하면 `api/compat.py`의 `_criteria_to_ranges()` 한 곳만 고치면 된다.

### 2. 가격 필터는 **환산월세** 기준이다

데이터가 국토부 실거래가라 **전세 3,300건 / 월세 5,585건이 섞여 있다.**
전세는 `price`(월세)가 0이라 월세로만 거르면 전세가 전부 통과하거나 전부 탈락한다. 그래서 필터는

```
환산월세 = 월세 + 보증금 × 0.055 / 12     (예: 전세 2.7억 → 124만원)
```

로 걸고, 응답에는 명세대로 `price`(월세)·`deposit`(보증금)을 **원본 그대로** 넣는다.

> ⚠️ **전세 매물은 `price`가 0으로 온다.** 카드에 "0만원/월"이라고 찍히면 안 되니
> `leaseType` 필드를 보고 분기해 주세요. `monthlyEquivalent`도 같이 보냅니다.

### 3. 명세에 없는 부가 필드

무시해도 되지만 쓰면 편한 것들.

| 필드 | 용도 |
|---|---|
| `leaseType` | `"전세"` / `"월세"` — 위 2번 때문에 사실상 필요 |
| `monthlyEquivalent` | 환산월세(만원). 정렬·비교용 |
| `buildingName` | 건물명 |
| `nearestStation` | `{ name, lines[], walkMin }` — 카드에 "신대방역 도보 3분" |

`commute` 응답에도 `path`(구간별 폴리라인 `[[lat,lng],…]`), `source`, `transfers`, `fare`가 더 온다.
**`path`를 쓰면 정류장을 직선으로 잇는 것보다 실제 선로 모양으로 그릴 수 있다** (한 구간에 수백 점).

## 좌표 문제는 해결됐다

명세의 "CSV 좌표가 동 단위라 지오코딩 권장" 건은 **이미 처리했다.**

- 원본 8,885건 → 중복 제거 8,348건 → 좌표 확보 실패 2건 제외 = **8,346건**
- `시군구 + 번지` 7,174개를 카카오 주소 API로 전부 지오코딩 (성공 7,173)
- 서울 **25개 자치구 · 296개 법정동** 전역, 좌표는 **100% 건물 단위**

동 대표점을 쓰면 실주소와 중앙값 741m 어긋나고 통근시간이 매물 절반에서 5분 넘게 틀어졌다.
지금은 그 오차가 없다.

## 확인용 호출

```bash
curl "localhost:8000/api/geocode?query=강남역"

curl -X POST localhost:8000/api/listings/search -H 'Content-Type: application/json' -d '{
  "p1": {"workLat":37.4979,"workLng":127.0276,"priceMin":0,"priceMax":70,"areaMin":5,"areaMax":12},
  "p2": {"workLat":37.5563,"workLng":126.9236,"priceMin":0,"priceMax":80,"areaMin":5,"areaMax":12},
  "limit": 5
}'

curl "localhost:8000/api/listings/2292/commute?p1WorkLat=37.4979&p1WorkLng=127.0276&p2WorkLat=37.5563&p2WorkLng=126.9236"
```

## 지도 SDK는 1번(위경도 + 실제 지도)으로 가정했다

모든 응답이 `lat`/`lng`를 준다. 명세의 2번(%좌표)으로 갈 일은 없을 것으로 본다.
